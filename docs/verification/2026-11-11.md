## Coverage

Contracts cover ordered dispatch, one-shot listeners, mutation during dispatch, nested events, failure isolation, falsy payloads, ownership, reverse cleanup order, reuse, rejected registration, async state transitions, cancellation and adapter failures.

Native checks use real `spawn` and `wait`, including cancellation while waiting, checkpoint cancellation, ignored running cancellation, errors after a wait, and real engine connection/instance adapters. The cancellation check observes the native runner finishing before asserting that cancelled work was suppressed.

Concurrency workloads include 128 async jobs with bounded computation, 256 one-shot signals fired by six tasks, repeated disconnection of 256 handles by six tasks, registration overlapping destruction across 256 signals, and concurrent registration/cleanup/destruction across 256 cleanup owners.

## Defects found and corrected

- Disconnected signal handles initially retained their owner. Records now release their active entry, which holds the callback and owner.
- Native compilation rejected postfix increments on table members; counters now use simple local variables in isolated closures.
- Native stress reproduced a nil-owner error when an expression-bodied helper reread an entry another task could clear. Capturing that immutable entry once corrected the failing workload. A post-registration destruction check also prevents a connection from escaping a concurrent close.
- Async outcomes publish complete records, and tests distinguish pending cancellation, running cancellation and late rejected requests.

These are scoped observations from this version. They do not establish every scheduler boundary or prove all possible interleavings. The source avoids a per-listener pair allocation during signal dispatch, but this record contains no comparative speed, FPS or memory benchmark.
